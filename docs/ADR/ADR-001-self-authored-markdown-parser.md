# ADR-001：Markdown 解析采用自研行扫描（而非 pulldown-cmark）

- 状态：已采纳（Accepted）
- 日期：2026-10-12
- 关联：SPEC §5、§6.1、§8、§14（决策 D23）
- 决策者：RandyWei

## 背景（Context）

码札是"源文本为真相"的 WYSIWYG Markdown 编辑器（SPEC §4.3）。Markdown 只是源文本的
**投影**：渲染时隐藏 `#`、`**`、`` ` `` 等语法标记，而光标、选区、命中测试、IME 定位
都必须能**精确映射回源文本的字节偏移**（SPEC §11）。此外，编辑需要**块级增量解析**
（只重解析改动的脏块），这就要求解析结果携带可靠、稳定的源字节范围。

候选解析实现：

- **A. 自研行扫描**（块级 + 行内）：自己按行扫描，直接产出精确字节偏移。
- **B. `pulldown-cmark` 0.13**：成熟的 CommonMark/GFM 解析器。
- **C. `comrak`**：同样是成熟实现，提供 `sourcepos`。

## 关键约束（实测）

对 `pulldown-cmark` 0.13.4 做了探针验证（`examples/probe.rs`，已删除）：

1. **没有块级偏移 API**：不存在 `get_source_range` / `get_offset` 之类的接口，`Event`
   不携带它所对应的源区间。
2. **仅部分事件能恢复偏移**：对 `Event::Text` / `Event::Code`，若其负载是
   `Cow::Borrowed`（借用了输入缓冲区），可用**指针差值**反推该片段在源文本中的位置。
3. **实体事件偏移不可恢复**：`&amp;` 之类会被解析成 `Event::Text("&")`，其负载是
   新分配的所有权字符串，指针不再指向输入缓冲，**无法**还原源偏移。
4. 因此无法稳定地给每个块/片段标注源字节范围，无法支撑"隐藏标记 + 精确落点 + 脏块重解析"。

对比可行性：

| 维度 | A. 自研行扫描 | B. pulldown-cmark | C. comrak |
|------|---------------|-------------------|-----------|
| 块级源字节偏移 | ✅ 直接产出 | ❌ 无 API | ⚠️ 有 `sourcepos`，但仅到节点粒度、行/列语义 |
| 行内片段偏移（可见 vs 标记） | ✅ 精确 | ❌ 仅 Borrowed 可借指针猜 | ⚠️ 需二次处理 |
| 实体（`&amp;`）偏移 | ✅ 不涉及（源即真相） | ❌ 不可恢复 | ⚠️ 同 B |
| 隐藏语法标记所需的"标记/文本"切分 | ✅ 原生 | ❌ 需自行重建 | ⚠️ 需自行重建 |
| 脏块增量重解析 | ✅ 行扫描天然适合 | ❌ 无块范围 | ⚠️ 受节点粒度限制 |
| 方言扩展（wiki-link/callout/标签） | ✅ 完全可控 | ⚠️ 受限于其事件模型 | ⚠️ 受限于其 AST |
| 依赖体积/维护成本 | ✅ 无外部依赖 | ✅ 轻量、快 | ⚠️ 体积与依赖更重 |
| 规范完备性（CommonMark 边界用例） | ⚠️ 需自行覆盖 | ✅ 极完备 | ✅ 很完备 |

## 决策（Decision）

采用 **A. 自研行扫描**：

- `mazha-md` 负责块级行扫描 + 行内扫描，输出**精确字节偏移**的 `Block` 森林与
  `SyntaxSpan`（可见文本 vs 语法标记，见 SPEC §5）。
- 每个块带 `range: Range<usize>`，可直接喂给 `mazha-core` 的 `OffsetMap` 计算
  显示↔源映射（隐藏区间 = 可见区间之补集）。
- `pulldown-cmark` **降级为 dev 依赖**：仅用于测试对照（oracle）与后续 HTML 导出参考，
  不进入运行时路径。

## 理由（Rationale）

1. **偏移是硬需求**：pulldown-cmark 拿不到稳定块级偏移，是整个 WYSIWYG 链路的地基。
2. **省一层重建**：自研扫描直接产出"标记/文本"切分，UI 与 `OffsetMap` 无需再从 AST 反推。
3. **增量友好**：按行扫描 + 块范围，天然支持"只重解析脏块"。
4. **方言可控**：知识库扩展（wiki-link/callout/front-matter/标签）可自由实现，不受第三方 AST 限制。
5. **零运行时依赖**：核心解析不引入外部 crate，体积与供应链更干净。

## 后果（Consequences）

- **代价**：需自行覆盖 CommonMark/GFM 的边界用例（定界符规则、惰性续行、嵌套等）。
  - 缓解：以 `pulldown-cmark` 作为 **dev 依赖 oracle** 做对照测试；后续可接入
    CommonMark 官方 spec 测试集。
  - 已知 MVP 取舍（见 SPEC §5）：`_` 不做词内强调；暂不支持引用式链接 `[a][b]`、
    实体 `&amp;`（按普通文本处理，源即真相故不影响无损保存）、跨行强调。
- **收益**：精确偏移、脏块增量、可扩展方言、无运行时解析依赖。
- **可回退点**：若未来自研维护成本失控，可评估切到 `comrak`（有 `sourcepos`），
  但届时仍需在节点粒度与 `OffsetMap` 之间补一层映射。

## 复审触发条件（Revisit when）

- CommonMark 边界用例覆盖率成为瓶颈，或对照测试长期出现无法收敛的差异；
- 需要引入自研扫描难以承担的复杂方言（如完整表格/公式语义解析且强制走第三方 AST）。
