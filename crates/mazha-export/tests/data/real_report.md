# 码札导出管线技术报告

本报告用于 **PDF 导出的真实文档回归**（风险项 R8）：覆盖排版质量、中文字体
覆盖与标记转义完备性。文档刻意写得较长，以验证多页排版与图片资源解析。

## 1. 背景与目标

码札（Mazha）采用纯 Rust 的共享核心，导出管线同样不依赖任何外部二进制。
选择 Typst 作为 PDF 引擎（决策 D21、D25），理由是排版质量与可编程模板能力。

关键目标：

1. 中文正文可正确回退到系统 CJK 字体渲染；
2. 行内样式（**粗体**、*斜体*、~~删除线~~、`行内代码`）与链接
   [Typst 官网](https://typst.app) 均正确；
3. 表格、代码块、引用、提示块等块级元素结构完整。

> 引用：导出结果应与编辑区所见保持一致（WYSIWYG）。
> 这是编辑器类产品的核心体验承诺。

> [!NOTE] 关于字体
> 内置字体不含 CJK 字形，因此导出时默认扫描系统字体作为回退。

## 2. 标记转义完备性

Typst 标记中的 `#`、`[`、`]`、`` ` ``、`$`、`*`、`_`、`<`、`>`、`@`、`/`、`~`、`=`
等字符具有结构含义，可见文本必须逐字符转义。下面给出若干易踩坑的样例：

- 价格写作 #100 而非 "一百"；
- 数组下标 a_0 与 a_1；
- 路径 a//b 与注释 /* c */；
- 邮箱 x@y.z 不应被当成引用；
- 行首的 = 号不应变成标题。
